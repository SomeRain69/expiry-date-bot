# 🛒 Expiry Date Bot

Telegram-бот, который следит за сроками годности продуктов и вовремя напоминает, что пора их использовать.
Добавляешь товар и дату, а бот сам пришлёт сообщение за 14 дней, за 7 дней и в день истечения срока.

**Демо:** <ссылка на бота в Telegram>

## Возможности

- Добавление товара через диалог: название, затем срок годности в формате `ДД.ММ.ГГГГ`
- Список товаров, отсортированный по ближайшему сроку
- Удаление отдельного товара и очистка всего списка (с подтверждением)
- Автоматические напоминания: за 14 дней, за 7 дней и в день истечения срока
- Данные каждого пользователя изолированы: чужие товары не видны и не удаляются
- Защита от дублей: один и тот же товар нельзя добавить дважды

## Как работают напоминания

Для каждого товара в базе хранится стадия отправленного напоминания (`notify_stage`):

| Стадия | Когда наступает | Что отправляется |
|:-:|---|---|
| 0 | до срока больше 14 дней | ничего |
| 1 | осталось 14 дней или меньше | ⚠️ предупреждение |
| 2 | осталось 7 дней или меньше | ⏰ напоминание |
| 3 | срок истекает сегодня или уже прошёл | 🚨 / ❌ финальное сообщение |

Проверка запускается раз в день в 09:00 (Europe/Moscow) и один раз при старте бота. Сообщение
отправляется только если расчётная стадия выше уже отправленной, поэтому повторов не бывает. Если бот
был недоступен и стадия пропущена, он отправит актуальную, не заваливая пользователя старыми
сообщениями. Если пользователь заблокировал бота, ошибка логируется и отправка не повторяется бесконечно.

## Стек

- **Python 3.11+**, `asyncio`
- **aiogram 3**: Telegram Bot API, FSM для диалога добавления товара
- **SQLAlchemy 2 (async) + asyncpg**: работа с PostgreSQL
- **Supabase (PostgreSQL)**: облачная база данных
- **APScheduler**: ежедневная проверка сроков
- **pydantic-settings**: конфигурация через переменные окружения
- **aiohttp**: минимальный HTTP-эндпоинт для проверки доступности на Render
- **Render + GitHub**: автодеплой при пуше в `master`

## Запуск локально

```bash
git clone <URL репозитория>
cd <папка репозитория>/bot

python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate

pip install -r requirements.txt
```

Создай файл `.env` рядом с `main.py`:

```env
BOT_TOKEN=токен_от_BotFather
ADMIN_ID=твой_telegram_id
DATABASE_URL=postgresql+asyncpg://пользователь:пароль@хост:5432/postgres
```

Запуск:

```bash
python main.py
```

При первом старте таблицы создаются автоматически.

## Деплой (бесплатно)

1. **База:** проект в [Supabase](https://supabase.com). Для подключения используется **Session pooler**
   (работает по IPv4). Строка подключения кладётся в `DATABASE_URL` в формате `postgresql+asyncpg://...`.
   Чтобы таблицу нельзя было читать через публичный REST API Supabase, включена защита строк:
   `ALTER TABLE items ENABLE ROW LEVEL SECURITY;` (бот ходит в базу напрямую и на неё не влияет).
2. **Хостинг:** Web Service на [Render](https://render.com) (бесплатный тариф).
   Start command: `python main.py`, Root Directory: `bot`.
   Переменные `BOT_TOKEN`, `ADMIN_ID`, `DATABASE_URL` задаются в разделе Environment.
3. **Чтобы сервис не засыпал:** бесплатный инстанс Render засыпает без входящих запросов,
   поэтому внешний монитор доступности периодически пингует корневой URL сервиса (его отдаёт `aiohttp`).
